# Afterimage generation workplace

Afterimage keeps ChatGPT subscription image work in Conversation and offers separate, optional OpenAI and Google image API routes on Images. The image API route uses the artist's own provider key and provider billing; saving a key uses Windows Credential Manager. The requested image provider and full model ID remain explicit. The native result is retained as an image artifact before it can be compared or added to the bound artwork. The provider job and candidate are identified by small JSON references; encoded image data is decoded inside the native service and never returned as model text.

The direct provider models are `gemini-3-pro-image` (default), `gemini-3.1-flash-image`, `gpt-image-2.5-sunburst`, and `gpt-image-2.5-flare`. ChatGPT's Sol/Luna choice is the conversation orchestrator, not a claim about the subscription image engine. A retained subscription image names that image engine only if the app server reports it. Direct API candidates record the requested image model and any model the provider reports in its response. The artifact store and native placement accept producer metadata independently of provider transport, leaving a path for later local-model producers without adding local inference now.

Native edit capture supports `scope=selection`, `scope=canvas`, or `scope=region` with integer document coordinates `{x,y,width,height}`. Region capture does not change the artist's live selection. Every job captures its document ID and source geometry when it starts, so tab changes cannot retarget later generation or placement. A selection retains its mask; a rectangular region has no mask and is placed at its recorded source rectangle. Placement fits the returned image into that rectangle without stretching its aspect ratio. Generated alternatives remain retained until the artist or agent chooses one. Long direct API jobs can be cancelled; a provider may bill a request it already accepted.

The [Google Generate Content image guide](https://ai.google.dev/gemini-api/docs/generate-content/image-generation) documents the `v1/models/...:generateContent` route and `generationConfig.imageConfig.aspectRatio` string such as `16:9`. The similarly named `responseFormat.image.aspectRatio` field is an enum on the REST schema and rejected literal `16:9` in the first live integration request. Afterimage uses `imageConfig`, including `imageSize=2K`. The [OpenAI image guide](https://developers.openai.com/api/docs/guides/image-generation) documents the Images generation/edit routes and custom output dimensions; the native service derives edit framing from the immutable captured source. Gemini has no explicit transparent-background setting in this route. OpenAI additions request transparent PNG output, and all retained candidates report transparency from decoded pixels rather than channel presence alone.

The opt-in neutral workflow `afterimage_live_api_artwork` produced `.afterimage/live-api-rooftop/rooftop-garden-robot.kra` and `.png`: Gemini Pro generated the 1536×864 three-panel rooftop robot comic; Sunburst edited the middle document region `[542,100,452,700]`; native placement preserved sampled pixels in the two side panels; editable SVG lettering, KRA save, PNG export, and KRA reopen passed. The two original candidates and their small metadata are under `.afterimage/live-api-rooftop/candidates/`; `semantic-evidence.json` records the correlated job, candidate, document, and layer IDs. This proof did not request transparent additions: both actual provider outputs are opaque RGB, as intended for replacing artwork. The rejected initial Google wire request is preserved as `rejected-responseformat-schema.txt`, with no candidate or image produced.

`.afterimage/provider-ui-preview/workplace-image-api.png` is a layout composition of the generated PNG beside a native dock widget, used to judge proportions. It is not a capture of a running Krita main window or its actual document view; the dock in that fixture has unrelated retained test candidates and no bound canvas.

Run native checks only through `afterimage/scripts/run-native-check.py`, which supplies the isolated runtime and offscreen Qt environment. `ApiImagesTest` covers both direct-provider artifact decoding and bounded references with local fake endpoints. `WorkflowTest` checks document-coordinate region capture and native retained placement. The live workflow is opt-in, requires `AFTERIMAGE_API_OUTPUT` and both provider keys, and uses ephemeral environment keys for the test only; it does not put Buddy V2 credentials in the app vault. The canonical key source for this workspace is `../buddy-v2/.env` through `../buddy-v2/scripts/import-buddy-env.ps1`.
